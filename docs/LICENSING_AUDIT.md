# AntennaFox – License Compliance Audit and Licensing Decision

Audit date: 2026-10-11. Audited revision: the pre-release working tree of 2026-10-11 (35 commits, single author;
the history was squashed into the 1.0.0 release commit, so that state is not reachable from the public history).
Sections 1–15 describe the tree as audited (MIT-licensed at the time) and are kept as the historical record;
"current" in those sections refers to that state. The implemented state is in section 16 and the updates below it.
Scope: the AntennaFox repository, its locked dependency set (`uv.lock`, 43 packages), the macOS PyInstaller bundle
produced by `packaging/macos/build.sh`, bundled assets, and the LibreVNA integration.

This document is an engineering compliance audit, not legal advice. Every statement is marked as one of:

- **Verified** – read from a file on disk, package metadata, or an authoritative upstream page (path/URL given).
- **Assessment** – a conclusion drawn from verified facts and the license texts.
- **Assumption / Unknown** – not verified in this audit; must be confirmed before relying on it.

---

## 1. Executive summary

1. **The project can be relicensed to the GNU GPL.** Every runtime dependency, every bundled native library whose
   license was verified, and every bundled asset carries a license that the FSF lists as compatible with GPLv3
   (MIT, BSD-2/3, PSF-2.0, Apache-2.0, LGPL-3.0, LGPL-2.1, Zlib, CC0, CC-BY-4.0, Bitstream Vera, GPL-2.0-or-later,
   GPL-3.0-or-later with GCC exception). No GPLv2-only, AGPL, proprietary or non-commercial component was found
   in the runtime or in the bundle. There is **no blocker** to GPLv3.
2. **Recommended license: `GPL-3.0-or-later`** for all original AntennaFox code, data and documentation.
   `GPL-3.0-only` is equally feasible with the current dependency set; the trade-offs are in section 14.
3. **Relicensing is practicable.** All 35 commits are by one author; there are no external
   contributions and no third-party code copied into the tree (section 4.6). Copyright is therefore concentrated in
   Altinum Technologies, which can relicense without collecting permissions (Assumption: the author acted for
   Altinum Technologies; see section 13).
4. **Qt / PySide6** is used via `PySide6-Essentials` 6.12.0 under the **LGPL-3.0-only** option. Only `QtCore`,
   `QtGui` and `QtWidgets` are imported; nine Essentials frameworks end up in the `.app`. None of the GPL-only Qt
   modules is bundled. The PyInstaller "one-dir" `.app` keeps Qt as separate, replaceable dynamic libraries, which
   satisfies LGPLv3 §4(d)(1) in substance. **However, the current bundle does not meet LGPLv3 §4(a)/(b)**: the
   PySide6 wheels ship no license text, and the repository and the `.app` contain neither the LGPLv3 nor the GPLv3
   text, no Qt copyright notice and no source offer for Qt. This must be fixed before any binary release (section 6).
5. **PyInstaller** 6.22.3 is GPL-2.0-or-later with the Bootloader Exception; applications built with it are not
   required to be GPL and need no PyInstaller notice. Compatible with GPLv3 either way.
6. **LibreVNA**: AntennaFox contains no LibreVNA source or binaries. It talks to the separately installed
   LibreVNA-GUI over a TCP socket using line-oriented SCPI text commands documented in LibreVNA's Programming
   Guide. Under the FSF's own criteria this is communication "at arm's length" between separate programs;
   AntennaFox is not a derivative work of LibreVNA-GUI. Choosing GPL-3.0-or-later removes even the residual
   theoretical risk, because LibreVNA is GPL-3.0.
7. **The current MIT distribution has an unnoticed issue**: the inspected `.app` contains GPL-3.0 `libreadline`
   (pulled in from the conda-forge Python used to build) without any notice or source offer. Under a GPLv3
   AntennaFox this is compatible, but the library should be excluded from the bundle anyway (section 10).
8. **Logo provenance**: `assets/branding/antennafox-logo-original.png` carries a signed C2PA manifest stating it was
   generated by OpenAI's image model (claim generator "OpenAI Media Service API", software agent "ChatGPT",
   digital source type `trainedAlgorithmicMedia`, created 2026-10-11T14:20:39Z). All other logo and icon files
   are derived from it. Under current US Copyright Office guidance and recent German case law, an image produced
   from prompts alone is unlikely to be protected by copyright at all. The practical consequence is that **no
   software license (MIT or GPL) can be relied on to control reuse of the logo; trademark law is the only
   realistic protection for the name and the mark** (sections 12 and 13).
9. **GPLv3 achieves the stated goal** – a rebranded or modified AntennaFox may be sold, but it must be distributed
   with complete corresponding source under the GPL, with notices intact. GPLv3 does **not** stop rebranding as
   such, does not protect the name/logo, and does not reach network-only use (section 11).
10. Before publication: replace `LICENSE`, add `licenses/` with LGPL-3.0 and GPL-3.0 texts and Qt notices, extend
    `THIRD_PARTY_NOTICES.md`, update `pyproject.toml`, README, About dialog, `Info.plist`, PyInstaller spec,
    `CONTRIBUTING.md`, add SPDX headers and a `TRADEMARKS.md`. The exact list is in section 15.

- Dependency manifests: `pyproject.toml`, `uv.lock` (43 packages, all from `https://pypi.org/simple`, plus the
  editable project – Verified via `grep '^source =' uv.lock`).
- Installed distributions: `uv tree`, `uv pip list`, and `importlib.metadata` for every distribution in `.venv`
  (Python 3.12.10, conda-forge build). `License-Expression`, `License`, `Classifier`, `License-File` and the license
  files inside `.venv/lib/python3.12/site-packages/` were read for every package.
- PyInstaller and its companions (not installed in `.venv`, only in the `package` extra) were installed into a
  scratch virtual environment at the locked versions and their metadata and `COPYING.txt` read.
- Source review: all files under `src/antennafox/`, `tests/`, `scripts/`, `packaging/`; grep for `PySide6.*`
  imports and for attribution markers (`copyright`, `license`, `adapted from`, `based on`, `ported`, `stackoverflow`,
  `github.com`, URLs).
- Bundle review: the existing `dist/AntennaFox.app` (built 2026-10-11 17:53 with the same spec; the lockfile is
  newer, so a fresh build must be re-inspected before release). All `.dylib`/`.so`/font/license files were listed.
- Assets: PNG chunk inspection of every image in `assets/`, `src/antennafox/assets/`, `packaging/macos/`.
- Upstream sources: Qt licensing pages, Qt for Python licensing page, LibreVNA repository and `LICENSE`, PyInstaller
  license page, DejaVu license page, FSF license list and GPL FAQ, US Copyright Office report (January 29, 2025).

## 3. Licensing objective

The maintainer's objective is that AntennaFox, including modified or rebranded derivatives, remains open source:
anyone redistributing a derivative must provide the corresponding source under the same terms. Commercial use and
commercial redistribution are to remain permitted; proprietary (closed-source) redistribution is to be prevented.

The MIT License cannot deliver this: it permits closed-source redistribution subject only to retaining the copyright
and permission notice (the former MIT `LICENSE`, lines 11–12). A strong copyleft license is required. The GNU GPL version 3 is the
standard choice for a desktop application in this dependency landscape; the AGPL adds nothing useful for a local
desktop program; the LGPL/MPL would not reach the whole derivative application. The remainder of this document
verifies that GPLv3 is compatible with everything AntennaFox ships.

## 7. LibreVNA-specific findings

### 7.1 Facts (Verified)

- Upstream: https://github.com/jankae/LibreVNA, `LICENSE` = GNU General Public License v3, 29 June 2007
  (fetched from `raw.githubusercontent.com/jankae/LibreVNA/master/LICENSE`). Covers hardware design files,
  firmware and the `LibreVNA-GUI` (`Software/PC_Application/LibreVNA-GUI`). The README states: "If you would like
  to control the LibreVNA with a script, see the SCPI Programming Guide" (`Documentation/UserManual/ProgrammingGuide.pdf`).
- AntennaFox `src/antennafox/instrument/`:
  - `scpi_transport.py` (212 lines): opens a TCP socket (`socket.create_connection`) to `127.0.0.1:19542`,
    sends ASCII lines terminated by `\n`, reads `\n`-terminated replies, uses `*IDN?` as a sentinel and `*ESR?`/`*ESE`
    for error detection and resynchronisation. No binary protocol, no shared memory, no library loading.
  - `librevna.py` (375 lines): drives the sweep with standard SCPI mnemonics (`:DEV:MODE`, `:VNA:ACQ:STOP`,
    `:VNA:FREQ:START/STOP`, `:VNA:ACQ:POINTS/IFBW/AVG`, `:VNA:STIM:LVL`, `:VNA:ACQ:SINGLE TRUE`, `:VNA:ACQ:FIN?`,
    `:VNA:TRAC:DATA?`), parses the documented `[f,re,im],...` text format with NumPy. The module docstring says the
    sequence was "chosen from the 1.6.5 VNA::SetSingleSweep/ConfigureDevice/SettingsChanged logic", i.e. the author
    read the GPL sources to understand *behaviour*; no C++ code, data structure or non-trivial algorithm is
    reproduced – the Python code consists of string commands, polling loops and validation.
  - `gui_emulator.py` (361 lines; now `instrument/librevna/emulator.py`): a test server that emulates "LibreVNA-GUI 1.6.5 SCPI behaviour"; docstring:
    "Emulated semantics (from upstream scpi.cpp / vna.cpp / tracewidget.cpp)". It reproduces the externally
    observable protocol (no reply on error + CME bit, `EMPTY`, `[f,re,im]` format, single-client behaviour) and the
    list of command names returned by `*LST?`. The implementation (dataclass fault injection, alias table, synthetic
    antenna models) has no structural correspondence to the C++ GUI.
  - `base.py`, `simulated.py`, `antenna_models.py` (now `instrument/simulated/backend.py` and `models.py`): project-original abstractions and synthetic models.
- Nothing from the LibreVNA repository is vendored: no C/C++ sources, no `LibreVNA-GUI` binary, no firmware, no
  calibration files, no icons/strings. The `.app` bundle contains no LibreVNA artefact (Verified by listing).
- `THIRD_PARTY_NOTICES.md`, `README.md` ("independent open-source project … not officially affiliated with or
  endorsed by the LibreVNA developers") and the About dialog carry non-affiliation statements (Verified).

### 7.2 Assessment

1. **Integration type**: communication with a separately installed GPL program through a network socket using a
   documented, text-based, instrument-industry protocol (SCPI, IEEE 488.2 mnemonics `*IDN?`, `*ESR?`, `*CLS`,
   `*ESE`). The data exchanged is flat text: numbers, `TRUE/FALSE`, comma-separated triplets. The FSF's GPL FAQ
   ("MereAggregation") states that "pipes, sockets and command-line arguments are communication mechanisms normally
   used between two separate programs", and that only communication "intimate enough, exchanging complex internal
   data structures" could make two parts one program. SCPI text over TCP is the opposite of intimate: it is the same
   interface any Keysight-style instrument exposes, and LibreVNA publishes it precisely for third-party scripts.
   Assessment: **AntennaFox is a separate program, not a derivative work of LibreVNA-GUI.** AntennaFox also does not
   distribute LibreVNA-GUI, so there is not even a GPL "aggregate" to consider.
2. **Independent implementation of a documented interface**: yes – command names and response formats are
   functional interface facts documented in the Programming Guide; reproducing them (including in the emulator's
   `*LST?` list) is not copying protectable expression. Residual point: the behaviour was derived in part from reading
   GPL source code rather than solely from the PDF. This is normal for interoperability work and does not make the
   Python code a copy; but it is not a clean-room implementation, and the docstrings say so. Under MIT this is a
   small theoretical exposure; **under GPL-3.0-or-later it disappears entirely**, because even if any part were deemed
   derived from GPL-3.0 code, the licenses would be compatible.
3. **Imports / modified LibreVNA code / bundled GPL binaries**: none (Verified).
4. **Hardware/firmware**: AntennaFox never touches USB (`README`, `docs/LIBREVNA_INTEGRATION.md`; Verified – no
   `usb`, `serial` or `hid` imports).
5. **Naming**: "LibreVNA" is a project name of Jan Käberich / the LibreVNA contributors. AntennaFox uses it
   descriptively ("Antenna Analysis GUI for LibreVNA"). Whether "LibreVNA" is a registered trademark is **Unknown**;
   descriptive compatibility statements are permissible in any case, and the existing non-affiliation disclaimers
   should be kept in README, About dialog and `TRADEMARKS.md`. Do not use LibreVNA logos (none are used today).

## 11. Redistribution and copyleft protection – what GPLv3 does and does not deliver

Assuming AntennaFox is published under GPL-3.0-or-later:

**What another developer or company may do**
- Use AntennaFox for any purpose, including commercially and internally, without any obligation (GPLv3 §2, §0:
  running the program is unrestricted; internal modification without conveying triggers nothing).
- Modify it, fork it, rename and rebrand it, integrate it into a larger GPL-compatible product.
- Sell copies or charge for support, installation, or a download (GPL FAQ "DoesTheGPLAllowMoney": "Yes, the GPL
  allows everyone to do this … there is no limit on what price you can charge"). They may not, however, require a
  fee for *access to the source* beyond the §6(b) reasonable media cost, and recipients may redistribute for free.

**What happens when they modify and redistribute**
- They must license the whole modified work under GPLv3 (or later, if we choose or-later) – §5(c). A proprietary
  or "source-available only to customers" model is not possible: every recipient of the binary must receive or be
  offered the complete corresponding source (§6) and receives the GPL rights (FAQ: distribution under NDA is not
  allowed; "your modified versions must carry all the freedoms stated in the GPL").
- They must mark the work as modified with a relevant date (§5(a)), keep all existing notices intact (§4, §5(b)),
  keep the "Appropriate Legal Notices" in interactive interfaces (§5(d), e.g. the About dialog's copyright and
  license statement), and may not add further restrictions (§10) nor technical measures (§3, §6 "User Product"
  Installation Information).
- Our copyright notices and the third-party notices must remain; they may add their own copyright lines.

**Mere rebranding**
- Changing the name, logo and colours and shipping it closed-source is exactly what GPLv3 prevents: the rebranded
  binary is a modified version and must come with GPL source. Rebranding itself is legal and – if we enforce
  trademarks – even desirable, because it stops forks from being mistaken for the official AntennaFox. The GPL does
  not require a fork to be renamed; trademark policy does (section 12).

**What GPLv3 does not provide**
- No protection of the **name or logo**; GPLv3 §7(e) merely allows us to state that trademark rights are not granted.
- No reach into **unreleased/internal use**, SaaS-style use, or use of AntennaFox's *output* (reports, `.afox` files,
  Touchstone exports) – these are not covered works.
- No obligation to **contribute back** (upstream) or to notify us; forks may diverge silently.
- No protection against **clean-room re-implementation** of ideas, workflows, or the SCPI sequence – copyright does
  not cover functionality.
- No **patent** protection beyond §11's licensee patent grant; no protection against someone else's patents.
- No control over **commercial exploitation**: competitors may sell it; they just cannot close it.
- Compliance is self-enforced: violations must be noticed and pursued by the copyright holder (§8 termination).
  Keeping copyright concentrated (or a contributor agreement/DCO) keeps enforcement practicable.

## 12. Trademark and branding considerations

### 12.1 Copyright versus trademark

Copyright (the GPL) governs copying of the code and assets. Trademark law governs the use of signs that identify
the origin of goods/services. The two are independent: a GPL license grants no trademark rights (GPLv3 §7(e) allows
the licensor to decline them explicitly), and a trademark policy grants no copyright rights. A trademark comes into
existence through registration or, in some jurisdictions (US, and in Germany through "Verkehrsgeltung"), through
actual use in commerce; a `TRADEMARKS.md` file documents the policy but **does not by itself create or register a
trademark**.

### 12.2 Findings

- The visual identity consists of the name "AntennaFox", the fox logo, and the publisher name "Altinum
  Technologies"/"AltinumTechnologies" with the domain altinum.tech.
- At audit time `README.md`, `THIRD_PARTY_NOTICES.md` and `src/antennafox/__init__.py` (`COMPANY = "Altinum
  Technologies®"`) used the **® symbol**; today ® appears only in `__init__.py` (`COMPANY`), `NOTICE` and
  `TRADEMARKS.md`, while copyright notices name Altinum Technologies e.U. A web search found no registration for "Altinum" or "Altinum Technologies" in the result set;
  EUIPO/DPMA/USPTO registers were not directly queried. The maintainer subsequently stated that "Altinum
  Technologies" is a registered trademark listed in TMview; the ® symbol is therefore kept. Registration details
  were subsequently supplied by the maintainer and are recorded in `TRADEMARKS.md` (see R5).
- **Logo copyright is doubtful** (section 4.5 and 13): the logo was produced by a generative image model from
  prompts. The US Copyright Office's report *Copyright and Artificial Intelligence, Part 2: Copyrightability*
  (January 29, 2025) concludes: "Prompts alone, however, at this stage are unlikely to satisfy those requirements"
  and that outputs are protectable only where "a human has been able to determine the expressive elements they
  contain" (case-by-case). German courts have recently denied copyright to AI-generated logos where the prompts were
  too general (Munich Local Court, reported February 2026; Düsseldorf Higher Regional Court, 20 W 2/26, April 2026,
  requiring documented free creative choices in prompting/selection). The derived files (crop to 720×587, rounded
  icon, social preview) add only mechanical edits (`scripts/make_icons.py`), which do not create new protectable
  expression. **Consequently neither MIT nor GPL can be relied upon to prevent third parties from reusing the logo,
  and the logo's inclusion in the GPL'd tree does not "GPL" it in any meaningful way.** Trademark protection is
  independent of copyright originality and is the appropriate instrument for the name and the logo as used in
  commerce.
- The watermark action `c2pa.watermarked.unbound` in the manifest indicates an imperceptible watermark was applied by
  the generator; whether it survives the derived crops/resizes is Unknown. It has no licensing consequence but is a
  factual property of the artwork that should be known to the maintainers.
- Ownership vis-à-vis the generator's operator: OpenAI's Terms of Use are widely reported to assign to the user
  whatever rights OpenAI may hold in Output and to warn that Output may not be unique; the current text could not be
  retrieved in this audit (HTTP 403) – **Unknown**; the maintainer should archive the version of the terms in force on
  2026-10-11 together with the generation record.

## 14. Recommended final license

**Recommendation: `GPL-3.0-or-later` for all original AntennaFox source code, catalog data, documentation,
samples and (to the extent protectable) artwork; third-party components keep their own licenses.**

Why "or-later" rather than "only":

- Nothing in the dependency set distinguishes the two today: every component is compatible with GPLv3, and a
  recipient of a GPL-3.0-or-later work may always choose version 3.
- "or-later" is the FSF's recommendation and preserves compatibility with licenses that may be declared compatible
  only with a future GPL version (as happened with Apache-2.0 and GPLv3). It avoids a future dead end comparable to
  GPLv2-only projects today.
- The maintainer keeps control: AntennaFox itself continues to be released under GPLv3 terms; "or-later" is an
  option for recipients, and the copyleft guarantee (source disclosure) is identical under any future GPL version by
  the FSF's stated policy ("similar in spirit", GPLv3 §14).
- The one argument for "only" – certainty about the exact future terms – is weak for a project whose main
  dependency (Qt) is LGPL-3.0-only: if Qt ever moves to a newer LGPL, a GPL-3.0-only AntennaFox could not follow.

If the maintainer nevertheless prefers GPL-3.0-only, every finding in this document still holds; only the SPDX
identifier, the "or (at your option) any later version" sentence in headers, and the classifier change.

Additional GPLv3 §7 terms: add only §7(e) (trademark declination, section 12.3). Do not add §7(b)/(c)/(d) terms;
they are unnecessary and complicate compatibility.

Not recommended: AGPL-3.0 (no network-service scenario, raises adoption friction), LGPL/MPL (would permit
proprietary derivative applications), dual licensing (no commercial licensing plan stated, and Qt LGPL obligations
would remain anyway).
